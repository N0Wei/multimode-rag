# 多车型汽车手册 RAG：切分、入库与检索实施基准

状态：**三本手册前半部已完成真实向量化入库，普通/Agentic 文本模式和独立图片普通 RAG 已接入**。当前仅完成 15 题真实索引检索冒烟评测，结果见 `data/eval/results/multi_manual_smoke_real.json`；该集合小且偏容易，尚不能作为简历中的泛化效果或相对基线提升声明。完整质量评测和部署压测仍需继续。本文仍是开发、测试和简历表述的共同依据。

## 1. 目标与已确定的边界

- 支持宋 Ultra EV、汉 EV 闪充版、秦 MAX EV 三本用户手册，并按车型限定检索；车型对比时分别检索、分别引用，再合成对比答案。
- 保留两个**逻辑上独立**的知识库：文本/表格库与图片库。图片附近文本不进入文本库，避免挤占正文召回名额。
- 文本采用目录章节级父块、正文语义子块；只索引子块，通过 `parent_id` 回查父块。
- 图片库内部有两条召回通道：附近文本向量和图片视觉向量。两路结果以同一 `image_id` 合并去重。
- 默认普通 RAG、可选 Agentic RAG 的模式切换只影响文本问答；**图片检索与图片问答始终走普通 RAG**。
- 不复用 `multimodal_pdf_parse.py` 针对旧 PDF 的切分规则；它的存储接口和测试可供参考，但新手册必须走 MinerU 产物的新解析链路。
- 不为这一阶段增加 PostgreSQL、车辆关系表、异步任务队列、复杂图片布局匹配或操作步骤专用识别规则。

## 2. 输入、覆盖范围与可追溯性

原始 PDF：

| 车型 | PDF |
| --- | --- |
| 宋 Ultra EV | `data/宋Ultra EV用户手册20261016.pdf` |
| 汉 EV 闪充版 | `data/汉EV闪充版用户手册260827.pdf` |
| 秦 MAX EV | `data/秦MAX EV用户手册260902.pdf` |

当前仅有约前半本手册的离线 MinerU `flash + txt` 解析包，位于 `tmp/mineru_flash_txt_half/`，分别为 `宋Ultra_1-202.zip`、`汉EV_1-195.zip`、`秦MAX_1-200.zip`。每个包中的 `middle_json.json` 是正文、表格、图片块及位置的**切分主输入**；`images/` 是图片资产。`markdown.md` 只用于人工检查阅读顺序和排版，不作为标题层级或切分主输入。当前仓库尚未实现可复现的 MinerU 导入链路，不能把这些离线产物描述为已集成的在线解析能力。

每次入库都记录 `source_sha256`、解析模式/版本（能取得时）、`ingest_batch_id`、`ingested_at` 和实际覆盖的 PDF 物理页范围。MinerU 的 `page_idx` 为 **0 基**，对外引用页码统一用 **1 基 PDF 物理页码**；纸面印刷页码如不同，应单独存储，不能混用。仅解析半本时，超出覆盖范围不能回答成“手册没有说明”。

## 3. 目录与父块边界：本方案最重要的约束

父块是**目录中的完整主题章节**，不是 MinerU 恰好识别出的最小标题，也不是 PDF 书签中最深的标题。先按每本手册自己的纸面目录确定主题及下一同级主题，再用 PDF 书签和正文位置辅助找到起止点。同页有两个章节时，边界落在标题对应的正文块处，而不粗暴地以整页划分。

已核对的关键例子：

- 宋 Ultra EV、汉 EV 闪充版：`安全 → 安全气囊 → 安全气囊触发条件及注意事项` 是目标父章节。`安全气囊触发条件`、`安全气囊可能会展开的情况`、`安全气囊可能不会展开的情况` 是其下子标题。后者虽出现在 PDF 内置书签中，却不在纸面目录中成为新的父章节。
- 秦 MAX EV：`安全气囊触发条件及注意事项` 编为独立的 `1-3` 节，目录级数与另外两本不同。仍以**这一完整主题章节**为父块，不能全局写死“目录第三级”。

一个父块保存从该主题正文起点到下一个同级主题起点之前的完整文本与表格语义内容，并保存 `section_path`、起止页和来源块 ID。图片不作为父块正文文本插入。父块不向量化；完整父块用于溯源和必要时扩展上下文，**不等于每次都要把数页父块全文塞给生成模型**。

若目录、书签和 MinerU 标题冲突：纸面目录决定章节归属，正文标题与位置决定页内边界；不能确认时标记待人工复核，不自动把较低层标题升为父块。

## 4. 正文标准化与子块规则

从 `middle_json.json` 读取每页 `blocks`，保留类型、正文、归一化 `bbox`、源 `page_idx`、块序号和图片路径；过滤页眉、页脚、页码等非正文。跨页但属于同一父章节的内容连续组织。对双栏或左右图文混排，先沿用 MinerU 顺序，再通过样本检查发现并修复明显错序；不把 Markdown 的展示顺序当作权威。

**子块生成顺序：先按语义结构，再考虑长度。**

1. 正文小标题用作 `child_heading`，其下连续段落形成子块；连续短段可合并，过长段落只在自然断点再分。
2. 同一小标题下的短并列项整体保留。例如①～⑧虽被 MinerU 分成两个正文块，仍可合成同一个子块，不按八条硬拆。
3. 表格从 MinerU 提供的 HTML 还原表头和行。短表格整体保留；长表格按行组切，每个行组重复表头。表格文本进入文本库。表格截图默认只保留为可追溯资产，不自动作为普通图片入库。
4. `警告`、`温馨提示`等类型根据**明确文字标签**识别；框线或 `table` 类型本身不代表提示或警告。此类内容作为独立语义单元，保留标题和完整正文。
5. **暂不做**“连续步骤”“操作前条件”的专门识别或合并；这类内容先按一般段落/小标题规则处理。

首版不为了凑固定字数拆散完整语义单元。对特别长的纯正文块，可暂用约 **800 个汉字的软上限**，仅在自然段边界拆分；没有安全断点就保留并标记超长。这个数值是**待评测参数，不是冻结规则**；记录块长分布和召回结果后调整。拆分时保留子标题及少量上下文，避免孤立段落。

## 5. 图片记录及附近文本

- 每个有价值的 MinerU `image` 块生成一个图片记录；文件仍存于磁盘。按文件哈希去掉完全重复图片，记录原始出现位置。装饰性图、重复页眉图等由规则初筛并抽样人工检查。
- 初版关联规则固定为：在**同一 PDF 物理页、同一父章节**内，按 MinerU 正文块顺序为图片取**前一条和后一条正文 `text` 块**；不存在的一侧留空。排除页眉、页码和表格 HTML。不跨父章节抓取附近文本。
- 这两条正文只是**候选检索线索**，不是经过验证的图注。上下布局和左右布局都可能错联；允许少量错联，但必须保留原图、页码和位置，并做样本 QA。不得让纯文本模型凭附近文本声称看到了图片细节。
- 图片记录只进 `manual_images`：附近文本用普通文本 embedding 建索引；图片文件用视觉 embedding 建索引。两路对应同一个 `image_id`，不同维度的向量不能直接比较分数，可做排名融合。

## 6. 存储与元数据契约

首版目标为两个 Qdrant collection：`manual_text`（文本/表格子块）和 `manual_images`（图片记录，内部可用命名向量）。父块完整正文及其 ID 映射先存项目已有的 JSONL 式文档存储；不要求额外关系库。图片资产不存成 Qdrant payload 二进制。

| 字段 | 适用记录 | 用途 |
| --- | --- | --- |
| `model_name` | 全部 | 规范化车型名；查询时的主要过滤键，三本手册取不同固定值 |
| `doc_id`、`source_pdf`、`source_sha256` | 全部 | 手册身份与原件校验；同车型多版手册时进一步限定 |
| `manual_version` | 全部 | 仅原文可核实时填写；否则为 `null`，不从文件名推断 |
| `schema_version`、`ingest_batch_id`、`ingested_at` | 全部 | 切分模式、入库批次及时间追踪 |
| `section_id`、`section_title`、`section_path`、`section_number` | 全部 | 目录级父章节的唯一身份、展示标题和路径 |
| `chunk_id`、`chunk_type`、`parent_id` | 文本/表格子块 | 回查非向量化父块；`parent_id` 必须指向目录级父章节 |
| `child_heading`、`child_index` | 文本/表格子块 | 正文小标题和同父块内顺序；不改变父章节层级 |
| `page_start`、`page_end`、`source_block_ids` | 文本/表格子块 | 页码引用和切分追踪 |
| `image_id`、`image_path`、`page_number`、`bbox`、`bbox_coord_system` | 图片 | 图片定位、展示、去重和人工复核 |

`section_id` 应由 `doc_id + 目录路径/章节位置` 稳定生成，不能只用可能重复的标题文本。Qdrant payload 保留过滤和回溯所需的短字段；子块正文、图片附近文本等长内容作为可检索内容或独立文档保存，不重复塞进大量 metadata。对 `model_name`、需要频繁限定的 `doc_id` 建立 payload 过滤索引。

## 7. 查询、融合与答案链路

1. **车型解析**：用明确车型选择和规范化别名词表解析查询；问题中的明确车型与界面选择冲突时要求确认，不静默猜测。未选车型且无法识别时询问用户；对比问题产生多个独立车型查询。
2. **过滤先于候选截取**：Qdrant 向量查询附加 `model_name`，同车型多版时再加有效 `doc_id`。BM25 必须有**相同的车型/手册限定**，不能全库 BM25 后混入其他车型；不能全库 Top-K 后再过滤。
3. **文本召回**：文本向量和 BM25 各召回候选，做 RRF 融合；重排可作为可测开关。按 `parent_id` 去重和控制单父章节占比，返回相关子块、原始页码及父块上下文。回答使用足量原文证据，不因父块跨数页就无条件整块注入提示词。
4. **图片召回**：图片附近文本向量与视觉向量分别召回，在图片库内部融合，按 `image_id` 去重，返回少量图片和来源位置。图片结果不占文本结果配额。若要描述图像细节，必须让视觉模型看到对应图片；没有视觉能力时只回答附近正文能支持的内容。
5. **生成**：同一回答中的每条结论保留车型、手册和页码来源。比较回答按车型分栏或逐项呈现，不能把甲车型证据用于乙车型。没有足够证据或该页未解析时明确说明。
6. **模式切换**：普通 RAG 和 Agentic RAG 共用相同的文本检索基础设施与过滤契约；Agentic 只负责文本工具编排。图像链路始终普通 RAG，不进入 Agentic 的重试、规划或工具选择循环。

候选数、融合权重、重排阈值、图片返回数和上下文预算均为**评测参数**，先记录默认配置，不在没有数据的情况下宣称最佳值。文本向量、BM25、图片附近文本向量和视觉向量的分数不能未经校准直接相加。

## 8. 实施顺序与验收门槛

| 阶段 | 实施内容 | 进入下一阶段的条件 |
| --- | --- | --- |
| A. 解析规范化 | 解包 MinerU 产物、目录章节定位、块顺序与页码统一 | 三车各抽样检查目录边界、跨页、双栏、表格和图片位置；误判能定位到源块 |
| B. 切块产物 | 生成父块、文本/表格子块和图片记录，导出可审阅 JSONL | 所有子块 `parent_id` 可回查；第四级小标题没有被误升为父块；图片路径可打开 |
| C. 索引入库 | 构建两库、BM25 与批次 manifest；验证后启用新批次 | 车型过滤、文档数量、去重数量和覆盖页范围一致；失败不覆盖可用索引 |
| D. 检索接入 | 接入普通/Agentic 文本模式、独立图片普通 RAG、引用展示 | 单车型与多车型对比均不串证据；图片不挤占文本召回配额 |
| E. 评测对照 | 在**相同三本手册、相同问题集和覆盖范围**上对比基线 | 报告文本 Child/Parent Recall@K、MRR、图片 Recall@K、跨车型泄漏、引用正确性和延迟；只报告实测结果 |

验收中的硬性正确性检查：无跨车型证据混用；所有引用能回到实际 PDF 页和源块；所有图片路径存在；所有子块父 ID 存在；半本覆盖范围之外不作“手册未记载”的结论。质量与延迟指标需要在评测集上取得基线后设目标，不能预写提升百分比。

## 9. 变更规则

以下是**冻结的架构决策**：目录级完整主题作父块、正文小标题只作子块边界；文本/图片两个逻辑知识库；图片两路召回但只走普通 RAG；按车型在各召回通道内过滤；半本解析范围明确标识；不做操作步骤专用规则。

以下可在留下评测记录后调整：长块软上限、候选数量、RRF/重排参数、图片数量、上下文预算、错联图片的筛选策略。若开发中发现需要改变冻结决策，应先更新本文并说明原因，再改代码，避免实现和约定再次漂移。
