# P0 工程可信度审计

本文件区分已经由代码/测试验证的能力与尚未完成的工程能力，防止README、简历
和实现之间再次发生漂移。

## 已验证

- LangGraph主链路包含意图识别、复杂问题分解、结构化规划、工具执行、证据
  评分、单/多跳合成、声明级Grounding、Reflection与最终输出。
- Planner输出经过本地工具白名单、参数Schema和组合校验。
- Tool Executor具备请求级缓存、重复调用拦截和执行预算。
- 节点、模型和工具事件写入请求级`execution_trace`。
- 汽车手册解析包含目录感知分段、文本/表格/图片元素提取、父子块构建、图片
  附近文本绑定和重复图片过滤。
- 正式结果文件包含100题文本/表格评测与100题图片检索消融。
- `python scripts/verify_p0.py`当前执行23项离线核心测试并校验正式结果文件。

## 已实现但有边界

- 可观测性是请求级内存Trace，可选择上报LangSmith；尚无本地持久化查询。
- 缓存只在单次Agent运行内生效，不是跨用户语义缓存。
- 多轮上下文采用最近轮次裁剪，不是经过验证的长期记忆系统。
- 联网搜索使用博查MCP，依赖`uv`、网络和外部API Key。
- 当前正式评测来自单份示例汽车手册，不能外推到多车型生产效果。

## 第三方组件口径

当前仓库没有发现MinerU的导入或调用链路。多模态解析的主要代码位于
`multimodal_pdf_parse.py`，使用PyMuPDF/Pillow等完成目录感知元素提取与自定义
切块。因此在真正接入MinerU之前，README与简历不应声称“基于MinerU完成
PDF解析”。如果部分JSON数据曾离线通过仓库外MinerU生成，也必须补充可复现
脚本、版本和输入输出记录后才能作为项目实现描述。
